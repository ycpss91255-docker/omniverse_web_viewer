# Changelog

## [Unreleased]

### Fixed
- `stream-only` viewer: the recoverable producer-loss readout no longer claims a reconnect is under way (closes #60). It read `stream stopped -- reconnecting...`, but nothing reconnects: in the bundle shipped in the runtime image (`/app/stream-only/dist/assets/omniverse-webrtc-streaming-library-*.js`) `maxReconnects` is passed straight through as `maxSessionStartRetry` (`new bv({ maxSessionStartRetry: o.maxReconnects, ... })`) and every use of `sessionStartRetryLeft` belongs to the session-**start** retry decision (`> 0`, `-= 1`, `= 0`) — there is no mid-session reconnect path, so a producer that dies once the stream is up is never reconnected to. The message therefore promised a recovery that could not happen, for the whole ~15 s before the terminal state (#58 / #59) replaced it. The recoverable state now reads `stream stopped -- waiting for frames to resume...`, which is true whether or not the picture comes back. Copy change only: the state stays non-error (grey), still clears on the first rendered frame (#53), still escalates to the terminal `stream ended -- the source is gone. Reload once it is back.` after `TERMINAL_ESCALATION_MS` (#58 / #59), and the terminal latch (#57) is unchanged. `maxReconnects` is deliberately still 20 — it buys startup grace for a viewer opened before the Kit app finishes booting, and the explanatory comment in `packages/stream-core/src/buildStreamConfig.js` now also records that the viewer copy matches what the budget really does. A new unit spec locks the regression: neither producer-loss state may mention a reconnect.
- `stream-only` viewer: the terminal producer-loss state is reachable again (closes #58). #56 / #57 wired it to the streaming library's `onTerminate` handler, but **this library build never invokes that handler**, so a viewer whose producer had died sat on the recoverable `stream stopped -- reconnecting...` forever. Evidence, from the bundle shipped in the runtime image (`/app/stream-only/dist/assets/omniverse-webrtc-streaming-library-*.js`): `onTerminate` occurs exactly 4 times and none is a call site — twice as the error-code enum `SessionTerminatedByAnotherClient`, once inside the matching error message, once as the null entry of the defaults object; by contrast `onStart` (52), `onUpdate` (13) and `onStop` (7, with a real `onStopResult.bind(this)` dispatch) all have one. Confirmed live by SIGKILLing the Kit producer. The terminal state is now derived locally: `stopped()` arms a bounded escalation timer (`TERMINAL_ESCALATION_MS`, 15s) and, if no frame renders inside that window, escalates to the terminal `stream ended -- the source is gone. Reload once it is back.` — so the user-visible change is that the message now appears about 15 seconds after the picture stops, instead of never. A stream that comes back renders a frame, which disarms the escalation and clears the readout exactly as before (#53). The timer is injectable (`terminalDelayMs` / `setTimer` / `clearTimer`), so the unit specs cover escalate-on-timeout, cancel-on-recovery, re-arming and the #57 latch without any real waiting. `onStop` is unchanged; `onTerminate` stays wired as a belt-and-braces extra only, with the evidence recorded in `streamStatus.js` / `main.ts` so it is not assumed to fire again. `maxReconnects` was reviewed while here and deliberately left at 20 (library default 5): the bundle passes it through as `maxSessionStartRetry` and consumes it only in the session-**start** retry decision, so it plays no part in mid-session producer loss — lowering it would not make the terminal state arrive sooner and would only shorten the startup grace window for a viewer opened before the Kit app finishes booting.
- `stream-only` viewer: a producer that disappears mid-session is no longer silent (closes #56). The app wired only the streaming library's `onStart` handler, so a Kit process that died after the stream had started produced no UI change at all — since #53 the readout hides on the first rendered frame, the end state was a frozen or blank viewport with no text, while the library kept reconnecting in the background (`maxReconnects: 20`). `onStop` and `onTerminate` are now wired to two new `createStatusController` transitions: `stopped()` re-shows the readout as a recoverable `stream stopped -- reconnecting...` (a successful reconnect renders a frame, which clears it again), and `terminated()` shows a distinct terminal error (`stream ended -- the source is gone. Reload once it is back.`) that is sticky — a trailing stop or a stray video event cannot clear it. Both are consumed as bare signals (the library's message payload for these two handlers is not verifiable from this repo). The normal path is unchanged: the readout still clears on the first rendered frame (#53). `main.ts` stays thin DOM glue; the policy lives in `apps/stream-only/src/streamStatus.js` with `node --test` unit coverage.
- `stream-only` viewer: the `#stream-status` readout no longer persists as a centered caption over the live video (closes #53). It was set to `streaming <server>:<port>` on connect and never cleared, so the connect-time confirmation stayed on top of the rendering stream and reappeared on every reconnect. The readout is now hidden once `#remote-video` is actually rendering (first `playing` / `loadeddata` event) and re-shown only on error / reconnect, so it reads as the transient "connected to X" confirmation it was meant to be. The show/hide logic is extracted into `apps/stream-only/src/streamStatus.js` (`createStatusController`) with `node --test` unit coverage; `main.ts` stays thin DOM glue.

### Docs
- Phase-1 docs GA (S8): the 4-language README (`README.md` + `doc/README.{zh-TW,zh-CN,ja}.md`) rewritten from the pre-refactor single-app model to the current architecture — two served apps (`usd-viewer` upstream-unmodified + our own `stream-only`) selected at boot by `VIEWER_UI_MODE` as a serve-level app selector, the `stream-core` / apps / image layering, the boot-time config-injection contract (sentinels preserved as `*.js.tmpl`, re-rendered every boot, validation IS the escaping), `MEDIA_PORT` (D1, `stream-only` only) added to the env table, ports delivered via the `.env` mechanism (host.yaml = `public_ip` only, D8), the lean `runtime` deployable stage (`just run -t runtime -d`), and the sidecar multi-instance model (embed N times, one client per instance, D6). ### Added
- Tier-1 browser config-dial e2e (closes #47). A standalone, `@nvidia`-free Playwright + headless Chromium suite (`test/e2e/`) drives the REAL dist served by the `runtime` image and asserts the booted bundle dials the injected `SIGNALING_SERVER:SIGNALING_PORT` (and, for `stream-only`, the media port: pinned when `MEDIA_PORT` set, null/negotiate when unset, D1) — the browser layer the curl-200 runtime smoke never reached. It wraps `window.WebSocket` / `window.RTCPeerConnection` to record dial targets without importing the streaming library; the app dialing a dead test host (async failure) is expected. `stream-only` asserts on the new `owv:dial` event; `usd-viewer` is black-box (upstream unmodified, D2) and asserts on the raw WebSocket dial with a served-JS string-presence fallback. Runs per-PR via the build-worker `extra_stages: e2e-test` Dockerfile stage (`FROM runtime`) on the hosted builder — no GPU, no Isaac, no self-hosted runner.
- `owv:dial` DOM `CustomEvent` from the `stream-only` app: dispatched on `document` just before the stream connect with `detail: { server, port, mediaPort }`, letting an embedding host page observe exactly what the viewer is about to connect to. Behavior-neutral (does not affect the connection).
- Two-app image with `VIEWER_UI_MODE` as a serve-level app selector (S5, D2/D4/D7). The image now builds two distinct apps — `usd-viewer` (upstream `web-viewer-sample` built UNMODIFIED, server/port sentinels only) and `stream-only` (our own full-screen auto-connect app over `stream-core`, server/port + media sentinels) — into `/app/usd-viewer/dist` and `/app/stream-only/dist`. The entrypoint selects which app to serve by `VIEWER_UI_MODE` (`usd-viewer` default | `stream-only`), renders ONLY the active app's `*.js.tmpl` at boot, then `serve -s /app/${VIEWER_UI_MODE}/dist`. Dockerfile stages: `usd-viewer-build` + `stream-only-build` -> lean `runtime` (`FROM devel-base`: node + serve + both dists only, no toolchain / no `src/` / no node_modules) + `devel` (full toolchain, also carries both dists so the uniform entrypoint works interactively) + `runtime-test` (`FROM runtime`, serves+curls both dirs for HTTP 200).
- `MEDIA_PORT` knob (D1) for the `stream-only` app: optional integer `1..65535`; unset renders the media port as the literal `null` so the streaming library negotiates media via SDP (back-compat default), set pins it. Validated in the entrypoint and rejected fast when out of range / non-numeric. `usd-viewer` carries no media sentinel (upstream native SDP negotiation).
- `VIEWER_UI_MODE=usd-viewer` baked into the `runtime` / `devel` / `example` stage ENV defaults and added to `setup.conf [environment]` so standalone `just run` surfaces it.
- CI: `build_runtime: true` + `test_tools_version: v0.41.0` + a `RUNTIME_SMOKE_CMD` build arg that serves both app dists and curls each for HTTP 200, so the lean runtime + `runtime-test` are actually built and verified in CI.

### Changed
- BREAKING: `serve` Dockerfile stage renamed to lean `runtime` (`FROM devel-base`, not `FROM devel`); the `serve` stage is deleted. Consumers running `*/omniverse_web_viewer:serve` must switch to `:runtime` (coordinated isaac `post/run.sh` change is S7). The deployed image no longer drags the build toolchain / `src/` submodule / node_modules.
- BREAKING: `VIEWER_AUTO_LAUNCH` removed entirely — the env knob, the `__OWV_AUTOLAUNCH__` sentinel, the `__OWV_UI_MODE__` sentinel, and the `host.yaml viewer.auto_launch` read are all gone (D7). Auto-entry into a bare stream is now achieved by selecting `VIEWER_UI_MODE=stream-only` (our own app); `usd-viewer` stays interactive (landing screen + USD UI + any-app stream reached by clicking). `VIEWER_UI_MODE` is no longer rendered into a bundle — it selects which app's dist the entrypoint serves.
- bats smoke tests moved to `test/smoke/bats/` (D5, repo is multi-tool now); the `devel-test` stage COPYs from `test/smoke/bats/`. `omniverse_web_viewer_env.bats` rewritten to the app-selector + 3-sentinel model (per-mode dist dirs, media-port null/pinned, mode-select, host.yaml `viewer.ui_mode`, exported mode for the CMD).

### Added
- Embeddable stream demo site (`examples/embedded-site-demo`, closes #15). A self-contained vanilla TypeScript + Vite example that embeds an Isaac Sim / Kit stream directly into a "real website" page via a stream-only direct connect — both a showcase and a copy-pasteable developer reference. Its only runtime dependency is `@nvidia/omniverse-webrtc-streaming-library` (no React / bootstrap). Ships as a profile-gated Dockerfile `example` stage served on `EXAMPLE_PORT` (8080), independent of the main viewer (5173) so both can run at once (`just run -t example -d`); reuses the same entrypoint (`__OWV_SERVER__` / `__OWV_PORT__` substituted from `SIGNALING_SERVER` / `SIGNALING_PORT` env or `host.yaml`). The connect config factory `buildStreamConfig` is a pure ESM module with `node --test` unit coverage; the README documents both the direct-connect integration and the zero-code `<iframe>` alternative.
- Configurable UI mode and auto-launch (closes #14). A `viewer` config (`ui_mode`, `auto_launch`) lets the client default into `stream-only` and skip the "UI Option" selection screen — needed for Isaac Sim / non-USD-Viewer Kit apps. Org-owned `overlay/` files (`App.tsx`, `stream.config.json`) are layered onto the upstream sample at build time (the `src` submodule is read-only); the entrypoint resolves the values into the built JS with precedence host.yaml `viewer:` > `VIEWER_*` env > built-in default. Documented in `config/host.yaml.example`. Defaults (`usd-viewer` / `false`) keep the stock selection-screen behavior.
- Entrypoint reads `/etc/host.yaml` (when mounted) for `network.public_ip` → overrides `SIGNALING_SERVER`. Single source of truth across containers reading the same yaml (closes #11, aligns with ycpss91255-docker/isaac#65). Precedence: yaml > env var > `127.0.0.1` default.
- `serve` Dockerfile stage — profile-gated extras stage for detached server use. Base template auto-emits with `tty: false` / `stdin_open: false`, avoiding the `/dev/pts` permission error that the `devel` service's `tty: true` triggers under `privileged: false`. Usage: `just run -t serve -d` (closes #9).

### Fixed
- `setup.conf [gui] mode = off` — disable auto GUI detection. Web-viewer is a static file server with no display needed; auto mode triggered X11 mounts + `tty: true` that caused `/dev/pts` permission errors on hosts with active X11 sessions (closes #7).

### Changed
- Base subtree bumped `v0.34.1` -> `v0.41.0` (#43). Container ops move from `make` to `just` (root `Makefile` symlink replaced by `justfile`; e.g. `make run -- -t serve -d` -> `just run -t serve -d`, no `--` separator needed). Wrapper scripts under `script/` now symlink to `.base/script/docker/wrapper/`; the entrypoint logging helper moved to `.base/script/docker/runtime/logging.sh` (in-image `/usr/local/lib/base/logging.sh`); `setup.conf` `[deploy] runtime` renamed to `gpu_runtime`; CI workflows repinned `v0.38.0` -> `v0.41.0`; regenerated `compose.yaml` no longer binds `/dev:/dev` (device mounts are opt-in upstream).
- Entrypoint config substitution hardened and made idempotent (#17). The entrypoint now runs under `set -euo pipefail`, validates every resolved value (signaling-server charset, numeric port, `ui_mode` / `auto_launch` enums) and exits non-zero on invalid input instead of baking malformed JS or injecting sed/JS metacharacters, and strips trailing inline `# comments` from `host.yaml` values. Behavior change: a previously-silent bad value now fails the container fast. The served `*.js` is re-rendered from pristine `*.js.tmpl` templates on every boot (built once, preserved in the image), so a `docker restart` or a changed env / `host.yaml` is picked up on the next start — the old in-place edit baked the first-boot values and ignored later changes.
- Docs: updated the Isaac Sim stage reference in README x4 (`headless-stream` -> `stream`), tracking the rename in `ycpss91255-docker/isaac` (ADR-0014 in `ycpss91255-research/isaac`). Example reference only; no behavior change.
- `SIGNALING_SERVER`, `SIGNALING_PORT`, `SERVE_PORT` are now runtime environment variables instead of build args. Entrypoint replaces placeholders in built JS at container startup — one image build supports multiple instances with different ports (#4).
- CI: `build-worker.yaml` pinned `v0.34.1` → `v0.38.0`, added `submodules: recursive` so `src/` submodule is initialized during checkout (fixes CI build failure since repo creation).
