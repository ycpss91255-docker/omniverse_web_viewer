1. 雙 App 模型

容器內攜帶兩套獨立 app，由 VIEWER_UI_MODE 環境變數在啟動時選擇其一。兩套 app 共用同一個 entrypoint、同一個 serve 實例，差異在 UI 和 streaming library 整合方式。

2. npm Workspace 結構

Root omniverse-web-viewer-workspace 管理三個 workspace directory。src/（usd-viewer）是獨立的，不在 workspace 內。

omniverse-web-viewer-workspace (root)
  workspaces: [packages/*, apps/*, examples/*]

  packages/

  apps/
    stream-only/        # custom viewer app
      depends on stream-core (workspace link)

  examples/

  src/                  # OUTSIDE workspace
    usd-viewer          # upstream submodule, own package.json

4. stream-core Package 抽象

packages/stream-core/（188 行）是唯一碰 NVIDIA @nvidia/omniverse-webrtc-streaming-library 的 package。所有其他 code 透過這 4 個 export 間接使用 streaming library。

Export行數職責測試特性
buildStreamConfig 75 Pure factory: server + port + mediaPort → DIRECT stream config object DOM-free, node --test 直接跑
connectStream 40 Lazy import() streaming lib → AppStreamer.connect(DIRECT) _connect test seam（不需 registry image）
describeStreamError 67 Error code → human-readable message Pure function
index.js 6 Re-export barrel --
Lazy import 設計：connectStream() 用 dynamic import() 而非 top-level import。NVIDIA library 依賴 browser globals（window, document），top-level import 會在 Node.js test 環境 crash。Lazy import 讓 buildStreamConfig 的 unit test 可以在無 browser 環境下執行。
maxReconnects = 20（library default 是 5）。不是 mid-session reconnect budget：這個值只影響 session start retry（sessionStartRetryLeft）。Producer 在 stream 建立後死掉不會進這個路徑。設高是為了 startup grace：viewer 在 Kit app 還沒開好前保持重試初始 session setup。

5. 完整 Runtime 資料流

Container 不是 media proxy：StreamType.DIRECT 表示 browser 直接與 producer 建立 WebRTC peer connection。Container 只做兩件事：(1) 用 serve deliver 含 baked-in config 的 static files，(2) 提供 signaling 端點的初始位址。stream 建立後 container 可以消失，media 不受影響。
