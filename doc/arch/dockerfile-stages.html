1. 鑽石拓撲總覽

Dockerfile 不是線性 pipeline。11 個 stage 形成鑽石拓撲: devel-base 向下分支至 5 條平行路徑，builder stages 透過 COPY --from 匯流回 runtime 和 devel，再各自延伸出 test stages。

3. 為什麼是鑽石，不是線性

ADR-0001 記錄了三個核心約束推動了這個拓撲：

精實 runtime
runtime 移除所有 build 工具（npm/git/sudo），只保留 curl（health check 用）和 serve。如果 runtime FROM devel，移除動作會變成破壞性清理而非乾淨起始。FROM devel-base + 精確 purge 是更安全的路徑。
Cache 隔離
usd-viewer-build 和 stream-only-build 是獨立 stage。改 apps/stream-only/ 不會 invalidate src/ 的 npm cache，反之亦然。兩者可平行 build（BuildKit --parallel）。
Test 隔離
runtime-test 測試的是精實 image 的行為（serve + curl），不是 build 環境的行為。devel-test 測試的是 lint + spec，需要完整工具鏈。兩者 FROM 不同 parent 確保不會互相污染。
devel 保留 sudo
開發者進入 devel container 需要 sudo（裝 debug 工具）。runtime 的 SUDO_FORCE_REMOVE 不影響 devel，因為它們是 sibling，不是 parent-child。
